# Exercise Catalog sources

Research date: 2026-07-23. Sources are the projects' official repositories, documentation, and license pages. This is an engineering assessment, not legal advice.

## Recommendation

Seed a **local, versioned snapshot of wger's exercise catalogue**, not a runtime API integration. Import names/descriptions, primary and secondary muscles, equipment, categories, translations, and provenance into this app's own tables. Import still images only when that individual asset includes an acceptable Creative Commons license, author, and source URL. Bundle optimized copies for offline use and render attribution on the Exercise detail screen plus a consolidated Open Data page.

wger is the strongest source because it is actively maintained (release 2.6 shipped on June 17, 2026), exposes a documented REST/OpenAPI surface, tracks license and author fields on exercises, translations, images, and videos, and has first-party synchronization commands for exercises and media ([wger repository](https://github.com/wger-project/wger), [wger releases](https://github.com/wger-project/wger/releases), [wger sync documentation](https://wger.readthedocs.io/en/latest/administration/sync-data.html)). Its nested exercise representation includes category, primary/secondary muscles, equipment, translations, images, variations, and author history ([wger OpenAPI schema](https://gist.github.com/simplyEvgen/faa977ec9a740aaf9e3dacc1be911e64)). This directly fits the proposed Exercise Catalog.

Do **not** make workout logging or exercise browsing depend on wger.de being online. Run an explicit import during development or a reviewed update job, pin the upstream snapshot/version, and ship the resulting catalogue locally. The app remains fully usable offline; upstream changes arrive only through a controlled migration.

For gaps, let the Member create private Custom Exercises. After the first release, selectively supplement with the Unlicense `yuhonas/free-exercise-db` metadata only after a provenance/content-quality review. Do not initially redistribute that repository's still images: although the repository applies the Unlicense globally, its documented exercise schema contains image paths but no per-image creator, source, or license fields, so the repository alone does not establish that every contributor had rights to dedicate every image to the public domain.

## The linked ExerciseDB repository versus wger

The user-linked [`ExerciseDB/exercisedb-api`](https://github.com/ExerciseDB/exercisedb-api) does **not** contain an API implementation, client library, exercise dataset, or downloadable media catalogue. Its current tree contains only `README.md` and a copy of the AGPL-3.0 license, and its complete visible history is three commits made on 25 November 2025 ([repository history](https://github.com/ExerciseDB/exercisedb-api/commits/main/)). The README is a product landing page that links to AscendAPI/RapidAPI and externally hosted sample media. Its AGPL file licenses the material actually present in that repository; it is not evidence that the separately served 11,000-exercise API dataset is AGPL-licensed.

## Licence rules to implement

wger's application code is AGPL-3.0-or-later, but its initial exercise/ingredient data is additionally CC BY-SA 3.0 and current content can carry individual Creative Commons metadata; some images came from Wikipedia and retain their own source information ([wger licence documentation](https://wger.readthedocs.io/en/latest/)). CC BY-SA 3.0 permits commercial copying and adaptation, but requires appropriate credit, a license link, an indication of changes, and the same license on adaptations ([official CC BY-SA 3.0 deed](https://creativecommons.org/licenses/by-sa/3.0/deed.en)). Therefore:

- Preserve source title/ID/URL, creator and creator URL, exact license and license URL, original-object URL, derivative-source URL, upstream revision, and whether this app modified the content.
- Show credit and the license link with every imported image and make all catalogue credits available offline.
- Keep modified wger descriptions/images under the applicable CC BY-SA license. Do not imply the entire application code is CC BY-SA; license the imported/adapted content separately.
- Exclude any record or asset whose license/creator/source metadata is absent or contradictory. “Visible in an API” is not permission to redistribute.

The Unlicense used by `free-exercise-db` says anyone may copy, modify, publish, use, sell, or distribute the covered material for any purpose and imposes no attribution condition ([repository license](https://github.com/yuhonas/free-exercise-db/blob/main/LICENSE.md)). Still retain a courtesy source record and pinned commit. A blanket repository declaration cannot cure third-party media for which the contributor did not hold the necessary rights.

## Dubious or freemium sources to avoid

- **ExerciseDB / AscendAPI:** despite the AGPL badge on its two-file GitHub repository, the API content is separately all-rights-reserved and storage-restricted; see the dedicated comparison above. Its free V1 API is useful for evaluation, not as open seed data, and V2 free media is watermarked.
- **wrkout.xyz:** the official page offers only 100 requests/month on the £0 testing tier. Paid tiers add media and carry attribution/commercial restrictions ([official pricing](https://wrkout.xyz/)). The public Unlicense repository is separate from this commercial API; do not assume the API's richer content inherits the repository license.
- **Any GitHub dump with GIFs but no per-asset licence:** a code license badge does not necessarily license copied photography, drawings, or animations. Reject media unless the rights holder, source and permitted redistribution are explicit.

## Import shape

Treat upstream catalogues as build inputs, not live services. The import should map into stable internal IDs and retain a provenance record per localized description and asset:

`source`, `source_item_id`, `source_url`, `upstream_revision`, `license_id`, `license_url`, `creator`, `creator_url`, `original_object_url`, `derivative_source_url`, `modified`, and `attribution_text`.

Keep imported Exercises read-only in the app; local corrections should be explicit overlays so future snapshots can be diffed. Private Custom Exercises remain separate and are never pushed upstream. Before every catalogue refresh, generate a review report for additions, removals/merges, changed instructions, missing licenses and changed media hashes.
